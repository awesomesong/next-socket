# ADR-0001: 가격 비교 소스를 네이버 쇼핑 단일로 한정

- **Status**: Accepted (2026-05-26)
- **Context module**: [src/app/lib/scan/naverShopping.ts](../../src/app/lib/scan/naverShopping.ts)
- **관련**: [구현 문서](../../src/app/api/scan/README.md), [설계 archive](../design/scent-scanner.md)

## Context

원래 설계 ([design/scent-scanner.md §3](../design/scent-scanner.md))는 가격 비교 소스를 **네이버 + 쿠팡 + 11번가** 멀티 소스로 제안. 구매 결정 지원이 핵심 가치 제안이므로 더 많은 mall을 비교할수록 좋다는 가정.

구현 단계에서 다음을 확인:

- **쿠팡 파트너스 API**: 신청 승인 지연 + 향수 카테고리 결과 빈약. 비공식 스크래핑은 ToS 위반.
- **11번가**: 공식 가격 API 없음. 스크래핑/제휴 통합 비용 큼.
- **네이버 쇼핑 API**: 무료 25,000건/일, 한국 향수 시장 90% 커버, productType=2 카탈로그 매핑이 가격비교를 이미 제공.
- 다층 mall 통합 시 **정품/노이즈 분리 로직**을 mall마다 따로 튜닝해야 함 → 베타 단계엔 과도한 부담.

## Decision

가격 소스를 **네이버 쇼핑 API 단일**로 한정. 정품 신뢰도는 mall 다양화가 아니라 네이버 응답 안에서의 **다층 필터 + 신뢰 점수**로 확보.

신뢰 점수 (0~100) 합산:
- 화이트리스트 mall (+30) — 사람이 검증한 mall
- 향수 카테고리 분류 (+20)
- `productType=2` 카탈로그 매핑 (+20) — 자동 매핑이라 +50→+20으로 강등
- per-ml 단가 정상범위 (+10~20)

필수 차단: 샘플·디캔트·짝퉁 키워드 / 1~15ml 소분 / per-ml < ₩500 / 향수 외 카테고리 / title 핵심 토큰 불일치.

## Consequences

**Good**
- 통합 비용 1/3 수준, 베타 출시 일정 단축
- 단일 소스 안에서 필터 튜닝만 하면 됨 → 디버깅 표면적 작음
- 네이버 한도(25K/일)는 24h 캐싱으로 충분 대응

**Trade-off**
- "여러 mall 가격 비교" UX 가치는 줄어듦 — 다만 네이버 자체가 mall 통합 결과를 보여주므로 사용자 체감 손실은 작음
- 네이버 API 정책 변경/요금제 도입 시 단일 의존 리스크 → 추후 쿠팡 파트너스 승인 시 재검토

**되돌리는 조건**
- 네이버 API 한도 초과가 일상화 (캐싱으로도 부족)
- 한국 향수 mall 중 네이버 미커버 비중 > 30% 확인
- 쿠팡 파트너스 API 승인 + 제휴 수익화 모델 채택
